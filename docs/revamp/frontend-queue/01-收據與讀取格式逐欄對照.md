# 收據與讀取格式逐欄對照

本文依目前註冊的網站端點與 SQL 寫入程序，供待送清單、讀取同步與相關畫面使用。「規格 01／02／03」分別指 [總則](../operation-contract/01-操作規格-v0.4-總則.md)、[操作與點數](../operation-contract/02-操作規格-v0.4-操作與點數.md)、[連線讀取與未決](../operation-contract/03-操作規格-v0.4-連線讀取與未決.md)。表中的「省略」表示沒有該鍵，「可為 null」描述有鍵時的 JSON 值，空陣列可正常出現。欄位型別都是線上 JSON 型別，日期為 YYYY-MM-DD，時間字串可能用 ISO 8601 的 `Z` 或 `+00:00`，不應用字串相等判斷兩個時間是否相同。網站外層時間由 Node 產生，資料列時間由 PostgreSQL 輸出。 `server/v2/ops/submit.js:54-57`、`server/v2/db.js:107-113`、`server/db-v2/sql/040-receipts.sql:40-49`。

## 提交操作

`POST /api/v2/ops`，JSON 請求本文上限 512 KiB。直連的權杖放 `Authorization: Bearer <權杖>`，操作者由工作階段決定。提交逐筆開獨立交易，按輸入順序回收據。先驗權杖，再驗本文與班級。建班是班級預檢的例外，僅首筆的 `class.create`、兩處班級編號相同且符合小寫 UUID v4 才能對尚未存在的班級送入 SQL。 `server/v2/app.js:54-62`、`server/v2/auth/session.js:57-85`、`server/v2/ops/class-access.js:4-22`、`server/v2/ops/submit.js:14-22,40-68`。

## 錯誤與送出端處置

網站請求層級回 `{ "error": { "code": "…" } }`。 `error` 是物件、`error.code` 是字串，兩者皆必有且不可為 null。限流會帶 `error.retry_after`（整數秒數，不可為 null），登入桶忙碌才附 `error.reason`（字串 `bucket_busy`，不可為 null）。 `server/v2/errors.js:1-28`、`server/v2/auth/login-buckets.js:90-98`。

GAS 自己回錯時外層 HTTP 200，本文 `http_status=0`，錯誤在 `gas_error`。成功轉送時讀包裝內的 `http_status` 與原始 `body_text`；包裝不完整時依規格視為回應遺失。下表的「GAS」指前一種。沒有 HTTP 的 SQL 入口標為「內部」；確認或退回暫緩批次的老師操作，其 HTTP 200 收據也可內嵌成員的拒絕結果。 `server/v2/README.md:82-102`、`server/db-v2/sql/245-agent-held-confirmation.sql:56-103`、規格 03 §10.3。

重送沿用相同編號，退避 2、4、8 秒遞增至最長 60 秒。須重登或補通行碼時，原項目留在原位。定案的「請老師處理」與「回報」移入「需要處理」，後者標為程式錯誤。有些未保存的程式錯誤須等放棄回應才可結清。放棄後換帳號仍回 `CLASS_FORBIDDEN` 時，須老師選擇才能完整移入「需要處理」，之後只能再試放棄。依規格 01 §3.4、§4.6、§5。
